# Cold-read probe（写件时冷读校验 · SKILL.md 工作流第 12 步）

写件方写完交接件、收窗之前跑一次。读者必须是**无上下文**的新代理（新起的子代理 / 新会话），只给交接件路径；写件方自己读不算 —— 带着全部上下文的人看不见缺口。

## 给读者的题面（原样复制，替换 `<HANDOFF_PATH>`）

```text
你是一个刚开窗、没有任何前情的接收方。你拿到一份交接件：
<HANDOFF_PATH>

规则：
- 先用 Read 读完这份交接件全文。
- 件内写出了具体文件路径的，你可以用 Read 打开那个路径看（只一跳：被打开的文件里再引用的东西不再追）。不要运行任何命令，不要检索，不要打开件内没写出路径的文件。
- 指针能打开且里面确有所需内容 ⇒ 可解析；只有编号 / 代号而无路径、路径打不开、或打开后没有所需内容 ⇒ 不可解析。

读完后回答 6 题，能解析的用你自己的话写出内容：
Q1 首动作是什么？完成判据和停止条件？
Q2 授权边界：哪些可直接做，哪些须用户裁定或手跑？
Q3 上一窗用户新立的要求 / 裁定各是什么、具体指什么？
Q4 用户原话里指向本件之外内容的说法（「前窗」「前几窗」「我提过」「我记得」「后面我提出的某某」「见前件」等）逐条：所指内容能否解析？
Q5 已被纠正、下一窗不得重犯的错误？
Q6 未完成项各是什么、来由是什么？

对每一条「不可解析」，再标一个等级：
- 承重 = 不知道它，就做不对首动作、守不住授权边界、或理解错用户本窗的要求
- 背景 = 不影响上面三件事

输出格式：按 Q1–Q6 分节作答；最后两行严格写
UNRESOLVABLE_CRITICAL=<数字> :: <每条承重不可解析项一句话，; 分隔>
UNRESOLVABLE_ALL=<数字>
```

## 写件方拿到回答后

1. 逐条处理每个承重不可解析项：
   - 内容你知道 ⇒ 写进交接件（内容本身或可打开的路径），不只转用户原话，不用你的解释顶替用户所指；
   - 内容你也不知道（用户说过但没落在任何地方）⇒ 当窗问用户，把答案写进件；用户不在 ⇒ 留在 REMAINING。
2. 同时对照读者的 Q1–Q3 回答：读者对首动作 / 授权 / 用户要求的复述与你的本意不符 ⇒ 是件的写法问题，改件。
3. 在交接件里写一行记录（可放在任一 text 围栏内）：

```text
COLD_READ=READER <读者身份，如 无上下文子代理> · CRITICAL_BEFORE <n> · CRITICAL_AFTER <m> · REMAINING <剩余承重项一句话，; 分隔 | NONE>
```

`CRITICAL_AFTER` > 0 时，lint 报 WARN，下一窗开窗能看到剩余项。

## 已知盲区（试点读数，4 份已知件 × 3 轮）

- 能检出：用户原话里的悬空指代、用户要求只转原话而未写内容、授权范围缺项。
- 看不出：**起草方解释顶替**（件里写了起草方的理解，读者无从判断它错了）；**当前任务偏离用户跨窗的主线计划**（件内自洽时读者看不出）。这两类靠写件方对照用户原话自查，不靠冷读。
- 读者很少主动打开指针 —— 承重内容写在件内，比写成「见某文件」更可靠。
